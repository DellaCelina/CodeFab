[시나리오 09] 정적 바인딩(중첩 스코프) + 상수 연산 최적화 복합 시나리오
=========================================================================

참고 요구사항
  - 3일차 PDF: 실행 전 최적화 - 정적 바인딩(Resolver)으로 몇 단계 위
    스코프인지 미리 계산해 O(1)로 변수에 접근, 상수 연산 최적화
    (ConstantFolder)로 리터럴로만 이루어진 서브트리를 실행 전에 미리
    계산해 리터럴로 치환
  - 1일차 PDF: 블록 { } 진입/종료 시 변수 저장소 생성/소멸, 여러 개의
    로컬 저장소가 중첩될 때 가장 인접한 스코프부터 상위로 탐색

실행 방법 (Release 빌드, repo 루트에서 실행)
  CodeFab\x64\Release\CodeFab.exe run scenario09_static_binding_and_folding.txt

검증 목적
  1) 3단계로 중첩된 블록에서 같은 이름(a)이 셰도잉될 때, 이 프로젝트의
     Checker::Resolver가 IdentifierExpression::depth를 정확히 계산해
     Environment::lookupAt으로 즉시 접근하더라도(최적화 적용) 동적 조회와
     동일한 결과(가장 가까운 스코프의 값)를 내는지 확인한다. 즉,
     최적화가 적용되어도 프로그램의 관찰 가능한 동작(출력값)이 최적화
     이전과 달라지지 않아야 한다.
  2) for 반복문 안에서 매번 등장하는 순수 리터럴 연산식
     ((2 * 3 + 4 - 1) % 7)이 Checker::Optimizer(상수 폴딩)에 의해 실행 전에
     하나의 리터럴(2)로 미리 계산되더라도, 5번 반복한 총합이 최적화를
     적용하지 않았을 때와 동일한 값(10)이 나오는지 확인한다.

예상 표준출력 (순서대로)
  [모드: RUN]
  7
  100
  7
  10

각 줄 설명
  - 7   : 가장 안쪽 블록에서 print a -> depth 0(가장 가까운 스코프, 값 7)
  - 100 : 같은 블록에서 print ga -> 로컬에 없어 depth가 전역까지 이어짐(100)
  - 7   : 바깥 블록으로 나온 뒤 print a -> 그 블록에서 선언한 a(7)를 그대로 읽음
  - 10  : (2*3+4-1)%7 = 9%7 = 2, 5회 반복 누적 -> 2*5 = 10

성공 판정 기준
  - 종료 코드 0
  - 위 4개 줄이 순서대로 정확히 출력됨
  - (선택) 최적화 적용 전 코드와 결과를 비교해 출력이 동일함을 확인하면
    "최적화가 프로그램의 의미를 바꾸지 않는다"는 것을 더 확실히 검증할 수 있다.
